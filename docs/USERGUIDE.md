# 用户指南

> 面向三类角色：**赛事管理员**（搭比赛、管数据）、**参赛小组**（干活 + 上报 + 部署）、**评委与现场观众**（看大屏、点链接）。
> 部署与运维细节见 [README.md](../README.md)，需求背景见 [REQUIREMENTS.md](REQUIREMENTS.md)。
> 下文以线上实例 `http://47.108.217.153:50000` 为例，自建实例请替换为你的地址。

---

## 0. 一页速览

| 角色 | 你要做的事 | 入口 |
|---|---|---|
| 管理员 | 建活动 → 录名单 → 建项目发 accesskey → 把 skill 和配置发给各队 | `/admin` |
| 参赛小组 | 把配置放进项目根目录，让 AI Agent 执行 `report.js --next` 开始循环干活 | 项目根目录 |
| 评委/观众 | 看大屏进度，项目"已上线"后点「▶ 打开项目」体验作品 | `/` |

## 1. 赛事管理员指南

### 1.1 赛前准备（四步）

**① 创建活动**
后台 →「活动管理」→ 填活动名称和结束时间（结束时间用于大屏倒计时，可留空后补）→ 创建。第一个活动自动成为"当前活动"；之后每期的活动默认"待用"，上屏前再「设为当前」。

**② 录入名单（部门 → 小组）**
后台 →「名单管理」，注意左上角"管理活动"切换器——录的是哪一期的名单。三种方式：

- 手动：左侧加部门，选中部门后右侧加小组；
- CSV 批量导入：每行一条 `部门,小组`（小组可留空，支持表头）：
  ```csv
  部门,小组
  研发中心,先锋队
  研发中心,破晓小组
  市场部,闪电组
  ```
- 脚本导入：服务器上 `node scripts/seed.js --file 名单.json`（JSON 格式见 `data/seed-roster.json`）。

**③ 创建项目、发放 accesskey**
后台 →「项目与密钥」→ 选部门 → 选小组 → 填项目名 → 「创建并生成密钥」。系统自动生成 accesskey 并**预留一个空闲端口**，弹窗里有一键复制的配置 JSON——把它发给该小组。

**④ 发放上报 skill**
把仓库里 `skill/hackathon-reporter/` 整个目录发给各参赛小组（放进他们 AI Agent 的 skill 目录即可）。

### 1.2 比赛中

| 操作 | 位置 | 说明 |
|---|---|---|
| 看进度 | `/` 大屏 | 实时推送，无需刷新 |
| 换上屏的活动 | 活动管理 → 「设为当前」 | 所有已打开的大屏自动切换 |
| 禁言某个项目 | 项目列表 → 「吊销」 | 该队所有上报立即被拒；「恢复」可逆 |
| 管理项目进程 | 项目列表 →「部署」列 | 启动/停止/重启各队部署的应用；崩溃会自动重启（最多 10 次） |
| 调整端口区间 | 项目与密钥页顶部端口池条带 →「调整区间」 | 持久保存；新区间必须覆盖所有已预留端口 |

### 1.3 赛后与下期

- 项目「归档」：从大屏消失、**释放端口**、停止其部署进程（可恢复）；「彻底删除」连审计一起清除，不可逆；
- 删除活动：需先清空该活动的部门与进行中项目；
- 开下一期：新活动「设为当前」即可，上一期数据原样保留、互不影响。

## 2. 参赛小组指南

### 2.1 你会拿到什么

1. 一个 **accesskey**（`hk_` 开头的字符串）；
2. 一份配置文件模板（或直接拿到现成的 `hackathon.config.json`）；
3. 上报技能目录 `hackathon-reporter/`（装进你的 AI 编程 Agent 的技能库）。

把配置放到**参赛项目根目录**：

```json
{
  "serverUrl": "http://47.108.217.153:50000",
  "accessKey": "hk_你的密钥",
  "deployUrl": "http://47.108.217.153:4100",
  "deploy": { "type": "node", "start": "npm start", "install": true, "dir": "." },
  "verify": { "api": "npm run test:api", "e2e": "node check-e2e.js" }
}
```

> 端口（4100 这类）是报名时系统分配的，你的应用**必须监听它**才能被评委访问。

### 2.2 比赛工作循环（让 Agent 跟着流程走）

在你的项目根目录反复执行：

```bash
node <skill目录>/scripts/report.js --next
```

它会说：当前进度、下一个节点是什么、完成标准、建议动作、干完活后用哪条命令上报。照着做，上报，再 `--next`，直到显示"全部节点已完成"。

七个节点必须按顺序：**需求分析 → 方案设计 → 原型设计 → 代码开发 → 本地测试 → 上线部署 → 线上验收**。

### 2.3 上线部署（第 6 节点）

```bash
# Node 应用（推荐）：自动打包上传，服务端代你启动到分配端口
node report.js --deploy

# 纯前端静态站：只打包 dist 目录
node report.js --deploy --dir dist --type static
```

- 代码里监听 `process.env.PORT`（服务端注入分配的端口）；
- 启动命令默认取 `package.json` 的 `scripts.start`，也可 `--start "任意命令"`；
- 探活通过后**自动上报**部署节点，大屏上你们的项目链接立即点亮；
- 失败会打印应用日志末尾，按提示修复后重跑即可（重复部署是安全的，直接覆盖）。

### 2.4 线上验收（第 7 节点，自动化）

```bash
node report.js --verify          # 探活 → 接口测试 → E2E，全过自动上报
node report.js --verify --dry    # 只验证不上报（彩排用）
```

- `verify.api` / `verify.e2e` 是**你自己写的**测试命令（建议在 testing 节点就写好），运行时会注入 `DEPLOY_URL` 环境变量指向你的线上地址；
- 三关全过才算验收通过；任何一关失败都不会上报，修复后重跑；
- **不要**手改测试让验证"通过"，也不要用 `--stage acceptance` 手工申报——验收只认自动化结果。

### 2.5 出错了怎么办（速查）

| 现象 | 含义 | 处理 |
|---|---|---|
| `⏳ 上报过于频繁` | 两次成功上报间隔需 ≥10 秒 | CLI 会自动等待重试，无需处理 |
| `409 STAGE_OUT_OF_ORDER` | 漏报了前面的节点 | `--status` 看应补报的节点，补上即可，不会卡死流程 |
| `NETWORK_ERROR` | 连不上服务端（已自动重试 2 次） | 稍后重新执行同一命令 |
| `KEY_REVOKED` | 密钥被管理员吊销 | 联系管理员 |
| `DEPLOY_FAILED` + 日志 | 启动失败（依赖缺失/命令错误等） | 按日志修复后重跑 `--deploy` |
| 验收探活失败 | 应用没起来，或 config 缺 `deployUrl` | 用 `--url` 指向线上地址，或补配置 |

## 3. 评委与现场观众

大屏（`/`）从左到右、从上到下：

- **顶部**：赛事名称、实时连接指示灯（绿=正常）、比赛倒计时、管理后台入口；
- **KPI 栏**：部门数 / 小组数 / 项目总数 / 已部署上线数 / 验收完成数 / 整体完成率圆环；
- **部门矩阵**：部门 → 小组 → 项目卡。项目卡上的 **7 个圆点就是流程节点**：青色实心=已完成，黄色闪烁=当前进行到这，灰色=未开始；右侧百分比 = 完成节点数 ÷ 7；
- **状态徽章**：`等待启动`（灰，还没动静）→ `进行中`（青）→ `已上线`（绿，**「▶ 打开项目」按钮亮起，点击新开 Tab 体验作品**）→ `已完成`（金，验收通过 100%）；红色为已吊销；
- **右侧**：「新项目·等待启动」轮播（刚领号还没上报的队）和「实时动态」流（每一次上报/被拒都实时滚动）。

## 4. 常见问题（管理员视角）

| 问题 | 排查 |
|---|---|
| 大屏不更新 | 看左上角指示灯：红色=连接断开（会自动重连）；活动切换后不更新=没点「设为当前」 |
| 创建项目报"端口池已分配完毕" | 调大端口区间，或归档旧项目释放端口 |
| 调整区间被拒 | 有已预留端口在新区间外，错误信息会列出具体端口 |
| 项目链接打不开 | 依次查：该队应用是否真的起来了（部署列状态）→ 服务器防火墙 → **云安全组是否放行端口池区间**（最常见的坑） |
| 部署一直"启动中/已崩溃" | 后台点「重启」；仍失败让该队看 `--deploy` 返回的日志末尾 |
| 忘记管理密码 | 服务器上 `echo $ADMIN_PASSWORD` 或查 systemd 单元；改后 `systemctl restart hackathon-live` |
